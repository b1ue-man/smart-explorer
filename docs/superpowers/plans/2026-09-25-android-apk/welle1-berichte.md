### Abweichungen vom Plan
- CatchUpStatus has two additive fields beyond the contract: `admitted: usize` (jobs admitted to this run; done = admitted - queued - running) and `skipped: Vec<CatchUpSkip>` with `pub struct CatchUpSkip { pub job_id: String, pub job_name: String, pub reason: String }`. Reason: the contract says rejected jobs appear 'with reason in message/a list', and api.md bg.catchUp needs `result.skipped` as a list. `message` also contains a summary ('2 Jobs ausgeführt, 1 übersprungen', 'Keine fälligen Jobs', 'Abgebrochen', the pause reason, …).
- Additional public functions: `daemon::host_state() -> HostState` (read counterpart of set_host_state; avoids dead code on desktop) and `daemon::last_catch_up_ms() -> Option<i64>` (finish time of the last catch-up run of any outcome, persisted in sync_data_dir()/catchup.last, seconds × 1000; None = never or unreadable). Reason: api.md bg.status.lastCatchUpMs must survive a cold process start.
- All contract functions are compiled and exported on every platform, not only unix (portable Rust, no OS calls). Desktop never calls them: they report 'not running' there, and on Windows they are simply unused.
- In shared code, Android behaviour is not selected with #[cfg]. It is selected through (a) `autostart::DAEMON_IN_PROCESS = cfg!(target_os = "android")` for ipc_client routing, and (b) embedded mode (`live::is_embedded()`, set only by ensure_embedded_daemon) for the boot marker and in-process Share draining. Platform code itself lives in daemon/os/android and autostart/os/android.
- ipc_host default_home/default_device_name use `support_dirs::host()` first on every platform, not only with cfg(target_os = "android"). Desktop never sets host values (B1a contract), so desktop behaviour is unchanged. Linux-host tests of the facade (mobile, all(unix, test)) then see the same host values as Android.
- `running_job` and `active_job()` return the job's display name (the id when the name is blank), not the id.
- `run_daemon_with`/`Handoff` are crate-internal (pub(crate) in the private module run_loop) and not re-exported; only run_daemon (desktop) and ensure_embedded_daemon (Android) call them.
- `request_catch_up()` expects an initialized worker loop in this process. Otherwise it returns Err("Background-Worker läuft nicht"). The facade should call ensure_embedded_daemon(…) first (api.md bg.catchUp already waits).

### Offene Punkte
- Nothing is compile-verified: no local builds are allowed. Remote CI must build the Android target (aarch64/x86_64) and run the Linux host tests, and this depends on B1a's support_dirs contract and Android arms elsewhere (share/net/mount modules used by daemon/**).
- If an embedded worker generation ends through a panic (no stop control), its IPC listener thread keeps running on an unpublished port with the stopped ShareHost. It is harmless (the new generation publishes its own address) but a thread leak; ending through a stop control makes it exit within about 100 ms.
- On Android, job hooks (run_before/run_after) run with /system/bin/sh inside the app sandbox, and OnConnect triggers never fire (removable_drives is empty, as on Linux). The UI should reflect both limits.
- `lastCatchUpMs` is seconds precision × 1000 and counts runs of any outcome (including 'paused', 'sync off', 'canceled').
- If more than one app process ever hosted the worker, only the first would get the flock in sync_data_dir()/daemon-lock; the others' ensure_embedded_daemon would return Err. The plan uses a single process.
