# E-ENGINE – API-Delta

Stand: 2026-10-03. [Vollständiges Datei-Inventar und Abnahmesignale](../abnahme/E-ENGINE.md), [offene Grenzen](../anfragen/E-ENGINE.md). Alle folgenden neuen APIs sind bisync-interne `pub(super)`-Helfer; bestehende öffentliche Run-/Preview-/Apply-/Merge-/Versionsignaturen bleiben erhalten.

| Interne API | Vertrag / Anschluss |
|---|---|
| `backend_identity_migration::migrate(&PairLock, SyncEndpoints, &AtomicBool) -> io::Result<Vec<PairLock>>` | Unter aktuellem Lock vor `replica::identify`/State-Open; Returned Guards bis Ende von Run/Preview halten. Höchstens acht nachgewiesene previousIDs je Seite; beide geordneten Paarorientierungen importieren getrennt unter denselben physischen Locks. |
| `backend_identity_state::{Binding, Aliases}` | Private `pairs/<pair>/identity-aliases.json`, format 1: aktuelle/alte Pair-/Lock-/Backendidentitäten und exakte Roots, Pending/Complete; maximal 80 alte Paarkombinationen. Backlinks autorisieren bestehende unveränderte Versionmanifeste. Kein Decoder, keine Token-/Accountinferenz. |
| `backend_identity_state::{family, version_matches, lock_matches, replica_matches}` | Nur belegte alte Pair/Backend/Lock-Bindungen; echte Marker-/Volumereplikas bleiben exakt. Lediglich exakt gebundener alter location-Fallback darf zum aktuellen gleichen Endpointalias passen. Retention und gewöhnliche Backupsemantik bleiben erhalten. |
| `FeedIndex::new(&PairRecord, Side, &BTreeMap<String, ItemRecord>, &[VfsChange])`, `resolve(&VfsChange)` | Eindeutige vollständige ID-/Directorybasis. `FeedResolution::Rooted(ResolvedChange, Option<VfsMeta>)` oder `Outside`; Fehler wird Rebuild. Rootrelative Feeds behalten ihren bisherigen Vertrag; globale Accountevents benötigen belegte Parent-Ancestry. |
| `engine_change_feed::bootstrap(&mut SyncStateStore, &PairRecord, SyncEndpoints, &Baseline, BisyncOptions, &WalkFilter, &AtomicBool)` | Kontrolliert beide tatsächlichen Walks inklusive vollständiger eindeutiger Name-/IDgruppen; schreibt File-/Directoryindex und Cursor in einer Transaktion. Historische file-only Caches werden durch `mirror-rv2-ancestry:<settings digest>` invalidiert. |
| `Staged::bind(&mut self, &RunVersions, &VersionSide, rel: &str, checkpoint_allowed: bool)`; `require_backup(Sig)` | Additiv vor bestehendem `publish`. Apply bekommt bestehenden Recorded-Kontext; Mergeoriginale ebenso mit false. Restore liefert bereits gesicherte `Preserved.signature`. Kein Kontextfallback. |
| `replacement_publish::publish(&mut Staged, destination, &CapturedFile, verify, cancel)` | Bestehende `Staged::publish` delegiert mit unveränderter Signatur. Durable Intent vor reversiblem Hook; nur false erlaubt einmal bestehendes `promote_staged_replace`. Err/Lost ACK behält verbleibende Stage/Intent, kein zweiter Versuch. Tatsächliche kopierte Bytes/Zielzeit und volle Zielverifikation im Intentzweig. |
| `replacement_journal::{Binding, Observed, Intent}` | Private format-1 JSON-Intent: Pair/Lock/Owner/Backend/Root/Relative, `a/b`, tatsächliche Replika, Run, checkpoint_allowed, optionale Backup-Sig; exakte Stage-/Destination-/retained-Pfade, volle MD5-Digests/IDs. `.se-replace-<16 lowerhex>` verwendet die vorhandene VFS-Stagingkennung. |
| `replacement_recovery::relatives(&PairLock, &StateKey, SyncEndpoints) -> io::Result<Vec<String>>` | Read-only, streng validierte Owner desselben exakten Paars/Endpoints und passender physischer Replika; keine Mutation durch Preview/Single. |
| `replacement_recovery::recover_locked(&PairLock, &StateKey, SyncEndpoints, cross_mounts, cancel)` | Vor normalem State-Open/Plan; genaue Inhalts-/IDchecks, create-only Restore, echte Namespace-Bestätigung vor Cleanup. Keine eigenen Erfolgsframes; Merge/Restorecheckpoint bleiben ihren APIs vorbehalten. |
| `orchestration_plan::{pending_paths, protect_pending}`; `replica_state::{owner_from_token, pending_owner_keys}` | Vereinigter Pending-Merge-/Replacementschutz über aktuelle und umgekehrte geordnete Paarbindung, andere streng validierte Owner bei gleicher Replika sowie Legacy-AdHoc-Pendingzustand. Keine fremden Baselines übernehmen; Single prüft unter gehaltenem Lock. |

Privat sichtbar gemacht: `persistence::pair_id_parts`, `replica_state::replica_token` und die für die kohäsive Publish-Auslagerung nötigen Staged-Felder. Eigene sechs additive Modulregistrierungen sind im Inventar benannt. Kein neuer öffentlicher Consumeranschluss nötig: die freigegebenen Run-/Preview-/Single-/Apply-/Merge-/Versionsconsumer sind bereits angeschlossen; `preview_with(..., RunSettings)` bleibt erhalten.

Der Hauptagent integriert anschließend separat freigegebene Fixtures in die eine gemeinsame Remote-Suite. Produktänderungen und deren direkte Grenzen sind abgeschlossen; Laufzeitaussagen bleiben bis dahin unbestätigt.
