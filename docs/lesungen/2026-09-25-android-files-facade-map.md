# Android files facade map: browsing, filtering, transfers, delete, open/zip, connection cleanup

**Purpose.** Ground the API contract of the planned `native/src/mobile/` JSON/JNI facade for the
file-browsing, filtering, file-operation, transfer, open/zip and connection-removal-cleanup
surface. For every relevant `app/`-local function this records exact signatures, which `App`
state it touches, whether it imports `egui`/`eframe`, and whether it is already egui-free and
movable out of `app/` as-is. Read-only; no architecture verdict given.

**Existing readings used for context, not repeated:**
`docs/lesungen/2026-09-25-android-app-feature-map.md` (feature→API table, GUI persistence, IPC),
`docs/lesungen/2026-09-25-android-background-daemon-model.md` (daemon/mount/syncjobs internals),
`docs/lesungen/2026-09-25-android-core-ops-api-and-portability.md` (cfg/Android-compile audit,
`Backend` trait, scanner/filter/copy/analytics/zip/folder_index entry points — cited here by
file:line without re-deriving).

## 3. `TransferLane` — concurrent remote transfer engine

## Facade call recipes

Numbered call sequences. `App::*` calls are cited only to show the exact sequencing the desktop GUI already validated; a facade calls the underlying non-`app` functions directly (or the named egui-free `app`-local helper) rather than `impl App` methods.

### (1) List a directory for an endpoint string
1. Off the calling thread: `let (backend, resolved_path) = connect::resolve_endpoint(endpoint)?` (`connect/os/shared/resolution.rs:7`). Persist nothing yet — this is a live, in-memory `BackendHandle` for the session.
2. If `!backend.is_local()`, wrap it: `let backend = Arc::new(vfs::CachingBackend::new(backend))` (`vfs/core/cache.rs:75`), matching `cache_remote` (`app/core/support_paths.rs:361`). Keep this one `BackendHandle` alive for the whole browsing session/tab (do not re-resolve per listing) — mirrors `connect::RemoteState` held per tab.
3. Off the calling thread: `let metas = backend.list_dir(&resolved_path)?` (`vfs/core/core.rs:97`). Await this single result.
4. Render `VfsMeta {name, is_dir, is_symlink, size, mtime_ms, btime_ms, hidden, system, id, content_md5}` rows.
5. On explicit user refresh: `backend.invalidate_cache()` (`core.rs:380`) then repeat step 3 — do not re-`resolve_endpoint`.
6. On leaving the session/closing the tab: drop the `Arc<dyn Backend>` (no explicit close call exists in this surface).

### (2) Non-recursive filter + recursive filtered scan
**Local:**
1. Compute scope: `let prunes = filter::filter_prunes(&filter)` (`filter/core/scope.rs:16`). If not recursive: `ScanOpts {follow_symlinks:false, max_depth: Some(1), retention: None}`. If recursive and `prunes`: `let retention = filter::FilterRetention::new(filter.clone(), root_prefix.clone()); let max_depth = retention.max_depth();` then `ScanOpts {follow_symlinks:false, max_depth, retention: Some(Arc::new(retention))}`. If recursive and not `prunes`: `ScanOpts {follow_symlinks:false, max_depth: None, retention: None}`.
2. `let handle = scanner::start_scan(root, opts, tx)` (`scanner/os/shared.rs:58`); keep `handle.cancel`/`handle.truncated` for step 4.
3. Drain `rx` repeatedly: accumulate `ScanMessage::Entries`, update UI on `ScanMessage::Progress`, surface `ScanMessage::Error`/`FailedPaths`, stop on `ScanMessage::Done(progress)`.
4. Persist nothing durable (scans are not cached to disk); keep `entries` + the filter that pruned it (`scan_retention` equivalent) + `handle.truncated.load()` in memory for step 6.
5. Build the view: non-recursive → filter with `CompiledFilter::compile(&filter).matches(e, &root_prefix)` for `depth>0` entries, sort. Recursive → `recursive_tree::result_rows(&entries, &root_prefix, &filter, compare)` then `RecursiveView::displayed(&entries)` for the currently folded subset.
6. On a filter edit: `if filter::scan_restart_needed(scan_retention.as_ref(), truncated, &new_filter) { restart at step 1 } else { recompute the view in place (step 5) }`.

**Remote:** identical step 1 (retention is backend-agnostic); step 2 becomes `let handle = rscan::start_scan_backend(backend.clone(), root, max_depth, retention, tx)` (`rscan/os/shared/rscan.rs:53`); steps 3-6 unchanged (same `ScanMessage` stream).

**Remote server-side name search** (optional fast path, substring/glob only, never regex): if `backend.supports_search()`, build `agent_proto::SearchSpec {query, glob: mode==Glob, min_size:0, max_size:0, max_results:100_000, want_dirs: filter.include_dirs}` and call `rscan::start_search_backend(backend, root, spec, tx)` (`rscan/os/shared/search.rs:20`) instead of step 2; treat the results as an already-server-filtered flat list and clear the client-side name filter.

### (3) TransferLane: upload / download / remote-copy (incl. filtered recursive clipboard copy)
1. Maintain one `TransferLane::new(6)` (`transfer_jobs.rs:186`, `MAX_ACTIVE_TRANSFERS=6`) per app/session.
2. Build the request:
   - Local→remote, whole selection: `TransferRequest::Upload {paths, backend: dest_backend, dest_root}`.
   - Local→remote, filtered recursive (relative paths preserved): first `recursive_clipboard::clipboard_snapshot(seeds, &root_prefix)` (or the equivalent local walk) to get `Vec<ClipboardVirtualFile{abs,rel}>`, then `TransferRequest::UploadPairs {pairs: files.map(|f|(f.abs,f.rel)), backend: dest_backend, dest_root}`.
   - Remote→local: `TransferRequest::Download {backend: src_backend, files, dest_local, filter}`.
   - Remote→remote (incl. same server, incl. filtered): `TransferRequest::RemoteCopy {src: src_backend, files, tgt: tgt_backend, dest_root, filter}` — no separate "same server" fast path exists; expect the doubled `bytes_total` and the local-temp-bridge cost.
   - Remote→remote filtered recursive with a remote *source*: first `recursive_clipboard`-equivalent selection expansion, then either re-use `RemoteCopy` with `filter` set (server-side filtering during the walk) or pre-download via `download_clipboard_snapshot` and re-upload as `UploadPairs` if the destination differs from a plain copy shape.
   - **Move (cut) to/from a remote is unsupported** — reject it in the UI exactly like the desktop does, rather than attempting it through `TransferRequest`.
3. `lane.submit(request, &mut launch)` (`transfer_jobs.rs:203`) — await `Admission::Started` or show a queued-at-position state for `Admission::Queued(n)`.
4. Poll: `for finished in lane.poll() { report(finished) }` then `lane.fill(&mut launch)` to start any now-free queued request. Persist nothing beyond in-memory progress; the terminal `TransferMsg::Done{progress, errors, canceled}` is the only trustworthy completion signal.
5. On success (remote destination in the current view), re-list that directory once (mirrors `App::drain_transfers`'s `self.rescan()`) — do not patch the view incrementally.
6. Cancellation: `lane.cancel(index)` or `lane.cancel_all()`; on session teardown, `lane.shutdown()`.

**Local→local (incl. move/cut, explicit conflict policy):**
1. Admit one worker at a time (mirror `copy_job.rs`'s single-slot rule).
2. Whole/filtered selection with an explicit `Conflict` choice and structure preservation → `copy::start_copy_expanded(seeds, filter, CopyOptions{root, dest, preserve_structure, conflict, mode}, tx)`.
3. Plain clipboard paste / drag-drop (always `Conflict::Rename`) → `copy::start_copy_from_paths(paths, opts, tx)`.
4. Filtered virtual-clipboard paste (relative paths, explicit conflict) → `copy::start_copy_pairs(pairs, dest, conflict, tx)`.
5. Drain `CopyMsg::{Progress(CopyProgress), Done{progress, errors}}`; on `Done`, refresh the destination view if `mode == Move` or the caller asked for a refresh (mirrors `finish_copy_job`'s captured-mode rule, not a later-edited draft).

### (4) Delete: local recycle vs. permanent; remote permanent
1. Build `Vec<vfs::DeleteTarget{path, id, is_dir, is_symlink}>` from the selection, then collapse nested selections (drop a target under another selected directory target).
2. Resolve the route from `backend.delete_disposition()` (`None` for local) and the requested intent (default vs. explicit "delete permanently"), via the same table as `resolve_delete_route` (`delete_actions.rs:371-387`).
3. **Local recycle:** per target, `recycle_local_target(target, win32_rules)` — try `trash::delete(...)` directly; on a Win32-hostile name (only when targeting a Win32 filesystem), first `rename_to_safe_sibling` via `backend.rename_no_replace`, then trash under the new name.
4. **Local/remote permanent:** `vfs::remove_entry_controlled(backend, target, cancel, |progress| report(progress))` per target — two-phase Planning/Applying, budget-limited, re-verifies each item immediately before removing it.
5. **Remote recycle:** `backend.remove_dir(path)` or `backend.remove_file_id(path, id)` per target (non-recursive per call).
6. Await either a terminal `DeleteOutcome` (success path — apply `succeeded_paths` to the in-memory listing) or an explicit disconnect/panic (**never assume success without an explicit terminal message** — force a full re-list of the current directory instead, mirroring `mark_unconfirmed_delete_state`).
7. Persist nothing beyond the refreshed listing. Allow only one delete operation in flight per session.

### (5) Rename / new folder / new file
1. **Rename** — require exactly one selected item. Remote: reject a `/`/`\` in the new name client-side, then `backend.rename_no_replace(old, new)`. Local: if the target OS/backend follows Win32 naming (`local_names_follow_win32_rules()`), first check `types::win32_name_issue(&draft)` and refuse with the returned issue's label before calling `Backend::rename_no_replace` on a `LocalBackend`.
2. **New folder** — Remote: `find_remote_unique_name(backend, parent, |i| numbered "Neuer Ordner"/"Neuer Ordner (i)")` then `backend.mkdir_all(rjoin(parent,name))`. Local: loop `std::fs::create_dir` over the same numbered names until one succeeds.
3. **New file** — Remote: same unique-name search, then `vfs::unique_staging_path` + `backend.open_write(staged)` (empty) + `backend.rename_no_replace(staged, path)`, cleaning up the stage on failure. Local: `OpenOptions::create_new` loop over `"{base}.{ext}"`/`"{base} (i).{ext}"`.
4. Persist: nothing beyond triggering a re-list of the containing directory (local success also opens the new file for editing on desktop — optional for a facade). Await: a single `Result<String,String>` per operation (spawned off-thread for the remote branches).
5. If the mobile UI accepts a free-typed name for new folder/file (unlike the desktop's fixed templates), add the same `win32_name_issue` gate used for rename.

### (6) Open a remote file: download to temp, baseline capture, save-back with conflict detection
1. `let local_name = backend.download_name(&path, &name);` allocate `let dest = open_temp_path(&local_name)` (a fresh, app-private path per open — `<app_private_dir>/open-temp/<session_tag>/e<random>/<safe_name>` on desktop; use the platform's private cache/files dir on Android).
2. Register an in-memory edit record `{temp: dest, backend, remote_path: path, name, baseline_mtime: MAX, seen_mtime: 0, remote_known_mtime: 0, dirty: false, uploading: false}` **before** starting the download (so a crash mid-download still has a recovery record).
3. Off-thread: `let local_path = download_to_id(&*backend, &path, id, &dest)?;` and separately `let remote_mtime = backend.stat(&path)?.mtime_ms;` await both.
4. On success: set `baseline_mtime = seen_mtime = file_mtime_ms(&dest)`, `remote_known_mtime = remote_mtime`, `dirty = false`. Persist the recovery manifest (durable JSON: name/local/remote/dirty/uploading per open edit) **before** handing the file to any external viewer/editor Intent, in case the app process dies while the file is open.
5. Hand `local_path` to the platform's "open" Intent/viewer.
6. Poll periodically (≥1.5s) for a changed, **stable-across-two-polls** mtime on `dest`. On a stable change: spawn a save-back check: `let current = backend.stat(&remote_path)?.mtime_ms; if known != 0 && current > known { conflict(current) } else { upload_file(&*backend, &dest, &remote_path)? }`. `upload_file` is the one allowed-to-overwrite upload path (`CommitMode::Replace`).
7. On upload success: re-baseline to the new remote mtime, clear `dirty`. On conflict: **do not overwrite**; adopt the remote's mtime as the new baseline, keep `dirty = true`, surface a conflict message asking the user to reopen the remote version or save again to force an overwrite. On upload failure: clear `baseline_mtime` to force a retry on the next poll.
8. Update and re-persist the recovery manifest after every state change in steps 4/6/7.
9. On app/session startup, sweep any leftover open-temp session directories from a prior run whose owning process is no longer alive: delete ones with no/empty manifest, keep and offer recovery for ones with declared entries.

### (7) ZIP: open as backend, extract
1. **Open:** `let backend = zipfs::ZipBackend::open(&zip_path)?;` (synchronous — run off the calling thread for a large archive) then `backend.list_dir("/")` per recipe (1) to browse it; remember the containing folder path so an "eject/close archive" action can return to it. Treat the backend as read-only (every mutating call returns `PermissionDenied`).
2. **Extract:** off the calling thread, `let count = zipfs::extract_all(&zip_path, &dest_dir)?;` — there is no progress callback or cancellation token available from this function; if the facade needs either, it must be added as new code (there is no existing non-Windows caller to reuse). It overwrites existing files at `dest_dir` unconditionally.

### (8) Folder index: build, search, persist
1. **Build:** off-thread (the function spawns its own worker), `folder_index::FolderIndex::build_async(roots, persist_path, tx, cancel)?;` roots = the platform's enumerable storage volumes/home directory. Drain `IndexMsg::{Progress{count,current}, Complete(FolderIndex), Canceled, Failed(String)}`; on `Complete`, replace the in-memory index and, if a search query is pending, re-run it.
2. **Search:** on every query keystroke, synchronously call `index.search_scored(&query, 90)` and show the top ~30 immediately; then spawn a background stat-and-rank pass `folder_index::stat_and_rank(scored, 30)` tagged with an increasing sequence number, and only apply its result if the sequence still matches the latest query (discard stale results from a fast retype).
3. **Persist:** on any index mutation (a completed build, or an incremental insert/remove from a live-update mechanism if one is added), mark the index dirty; save at most every 30s via a background worker that clones the index before writing, and only clear the dirty flag after the clone was taken (so a mutation racing the save is never lost). On session/app teardown, always join any in-flight save, then do one final synchronous save if still dirty.
4. **Note:** this whole feature is compile-blocked for Android as the source is written today (missing `platform` module for `target_os="android"`, §8 above) — implementing this recipe requires the module-selection fix to land first.

### (9) Connection removal cleanup
1. Build the scope for what is being removed: `RemovedEndpointScope::for_direct_contact(id)` / `::for_room(profile_id, wire_id)` / `::for_saved_connection(&saved_connection)`.
2. Call the headless function directly (no `App` needed): `let report = app::cleanup_removed_endpoint_state(&scope);` — this rewrites `favorites.txt` and `dir_sort.tsv` on disk, stops any live mount matching the scope via the daemon, and collects (without deleting) the names of any sync job still referencing the removed endpoint.
3. Await the single `CleanupReport {favorites_removed, dir_sort_removed, mounts_stopped, tabs_closed: 0 (facade fills this in), mount_error, file_errors, orphaned_sync_jobs}` return value (synchronous call except for the mount-stop network round-trips it makes internally).
4. Facade-side follow-up (the part `cleanup_removed_endpoint_state` itself does not do): reload the in-memory favourites/dir-sort caches from the just-rewritten files; close or detach any open browsing session/tab whose endpoint prefix or local root matches `scope.matches_key(...)`; if any open remote-edit temp file (§6) belongs to the removed endpoint, treat it the same way (stop polling it, keep or discard its recovery record per the user's choice). Increment a facade-local `tabs_closed`/`sessions_closed` counter for the final summary if desired — `CleanupReport.tabs_closed` itself is only ever set by the GUI's own `cleanup_after_removal`, not by the headless function.
5. Report the merged summary (`report.summary_lines()` plus the facade's own closed-session count) to the user; if `mount_error` or any `file_errors` entry is present, surface it — cleanup is deliberately best-effort per store, never all-or-nothing.
