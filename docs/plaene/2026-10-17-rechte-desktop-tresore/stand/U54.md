1. `limiter_code` delegiert an `Limiter::code()` (U50), eigene Tabelle wäre doppelt; der Test hält alle zehn Varianten mit einem erschöpfenden `match` fest.
2. `limiter_text_for(ctx, progress)` ruft die reine Funktion `limiter_text_with(private, progress)`; sie ist ohne Laufzeit prüfbar. Private Aufgaben: `Source`/`Target` -> "Begrenzt durch das Laufwerk", `Remote` -> "Begrenzt durch Leitung oder Server" (feste Texte, nicht aus dem Engine-Text abgeschnitten); `Link`, `SeCpu`, `SeThread`, `Memory`, `Ramp`, `Idle` unverändert.
3. `set_private` setzt `limiter_text = None` (wie `message`), damit ein vor dem Umschalten gesetzter Text keinen Namen hält.
4. `ignoreUnknownKeys = true`, `explicitNulls = false` in `Core.json` (`A/core/Core.kt:46`) geprüft: alte Kerne ohne Schlüssel -> `null`.
5. U54-4 (Sensoren): `N/transfer/os/unix.rs` liest `/proc/stat` usw. bereits mit `None` bei Lesefehler (U50); keine Änderung in diesem Paket.
